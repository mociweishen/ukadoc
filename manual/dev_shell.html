准备作为立绘的图片

首先准备一张作为立绘的图片。

可以自己绘制，也可以使用名为“Free Shell”的现成资源包。

可以从以下网站寻找Free Shell：

freeshell wiki

在人格中，图像格式的基本格式为png。

不支持jpg、bmp等格式（但在SSP中可以使用）。

使用PNG格式时，大小和颜色数均无限制，但透明度基本无效（仅在SSP中根据设置可生效。详见后文的半透明表面部分）。

若希望减小文件大小，请使用相关工具进行色彩缩减。

构成Shell的一张张立绘以及后文所述的动画一帧，均以表面为单位进行管理。

表面可通过准备名为“surface○○.png”（○○处可填入0或更大的数字）的图像，或通过后文所述的surfaces.txt将多张图像合成来生成。

surface0.png和surface10.png这两张图像基本上是必需的。

surface0.png是主体侧的基本表面，surface10.png则是另一侧的基本表面。

即使作为人格的只有角色一人而无需搭档，也请准备一张纯色填充的图像（即全部透明显示，详见后文）等作为surface10.png使用。

即使将表面命名为surface0000.png、surface0010.png等，也会被识别为与surface0.png和surface10.png相同。

在表面图像中，左上角的1个像素点会被视为“透明色”，在显示时以半透明效果呈现。

如果角色内部也有与透明色相同的颜色，那么该部分也会被透明化，因此请为透明色选用角色未使用过的色系。

编写descript.txt

descript.txt是用于设置该Shell基本信息的文件。

descript.txt若未正确准备，则该Shell将无法被Ghost识别。

首先，请将以下内容复制到名为descript.txt的文本文件中，并根据您的 Shell 类型将其修改为相应的内容。

charset,UTF-8
type,shell
name,这个Shell的名称

craftman,制作者名(仅限英文字母和数字)
craftmanw,制作者名(用中文书写也可以。)
craftmanurl,制作者的URL(分发网站的URL等)

charset请基本设定为UTF-8(原文为Shift_JIS)。

此外还有许多可设置的项目，但最低限度所需的仅以上这些（严格来说，只有name和type是必填项）。

此处未提及的设置以及各设置更为详细的说明，请参阅“Shell设定”页面。

举一个例子，要改变整个壳的基本气泡位置

sakura.balloon.offsetx,0
sakura.balloon.offsety,0
kero.balloon.offsetx,0
kero.balloon.offsety,0

就需要补充添加这样的项目。

sakura.balloon.offset用于修改主体侧气球的位置，kero.balloon.offsetが则用于修改另一侧气球的位置。

当数字增大时，x坐标会向角色一侧偏移，y坐标则会向下显示。

如果加上负值，显示位置会朝相反方向移动，x坐标会远离角色，y坐标则会向上显示。

即使要将换装显示在菜单中也需在descript.txt中进行相关描述，有关这方面的说明请参阅设置换装页面。

编写surfaces.txt

首先创建一个名为surfaces.txt的文本文件。

这是一个用于设置动画、合成图像以及在使用鼠标光标操控角色时设定碰撞检测等操作的文件。

也请一并参照“Shell - surfaces.txt”页面。

创建了surfaces.txt后，请先将以下内容复制到文件开头。

charset,UTF-8

descript
{
version,1
}

第一行应与descript.txtt文件采用相同的字符编码。如无特殊原因，使用UTF-8(原文为Shift_JIS)即可。

其后的各项说明，均为关于动画设置格式的设定。

若未作此说明，则必须按照旧版定义（SERIKO/1.x）编写动画相关代码。

本页所举示例均基于新版定义（SERIKO/2.0），请务必注意。

已按照旧定义编写的surfaces.txt，可通过以下工具从旧定义转换为新定义。

  • 适用于樱花编辑器的宏「SERIKO1to2.js」

    使用方法：安装樱花编辑器，并将其作为宏来使用。详细说明请参阅附带的readme.txt。

  • 将surfaces.txt从旧定义转换为新定义的工具

    使用方法：请在与surfaces.txt相同的文件夹中运行解压后的.exe文件。

编写surfaces.txt - 碰撞检测篇

让我们从为表面定义碰撞检测开始吧。

首先，请将以下内容追加到surfaces.txt中。

surface0
{
}

这表示在这个大括号 {} 内部，是对 surface0 进行设定的意思。

不仅限于碰撞检测，后续将提到的动画和element的设置也都会写在这里。

如果在此处按如下方式编写，则构成了碰撞检测的定义。

surface0
{
collision0,117,71,185,130,Face
collision1,115,174,174,217,Bust
}

如上所示，我们按照每个碰撞检测点的顺序依次写为collision0、collision1、collision2。

编号在同一个表面上请勿重复。

每个表面的最大碰撞数量为256个。

其后的四个数字是坐标指定。

以表面图像左上角为坐标原点0,0，按矩形左上角的x、y坐标，再接右下角的x、y坐标的顺序排列。

最后一个字符串是人格方使用的碰撞判定名称。

此外，即使多次设置相同名称（如上述的Face、Bust）的碰撞检测也无妨（例如，当希望将手定义为名为Hand的碰撞检测时，由于右手与左手的检测区域通常不相连，因此指定Hand的行也可能需要分成两行）。

获取碰撞检测坐标时Coordin工具非常方便。

将图像拖放到Coordin中，即可通过拖拽创建矩形碰撞判定。

坐标已自动复制到剪贴板，请将其粘贴到碰撞判定的数值中。

在MATERIA中，只需在设置里勾选“开发界面”，即可从“所有者绘制”菜单中查看碰撞判定区域。

在SSP中，进入“选项→偏好设置”的“常规”选项，开启开发者功能，然后打开“实用工具→开发人员界面”，即可通过显示碰撞判定来确认。

编写surfaces.txt - 动画篇

伺か中的动画（称为SERIKO）是通过连续绘制静止图像来实现的。

这里将简单介绍动画的执行时机、每一张静止画面的叠加方式等设置方法

以下以让surface0闪烁为例，说明动画的制作方法。

surface0
{
animation0.interval,sometimes
animation0.pattern0,overlayfast,100,50,0,0
animation0.pattern1,overlayfast,101,50,0,0
animation0.pattern2,overlayfast,100,50,0,0
animation0.pattern3,overlay,-1,100,0,0

collision0,117,71,185,130,Face
collision1,115,174,174,217,Bust
}

要对surface0.png进行动画处理，可按如下方式编写surface0，并在其下方的大括号（{}）内定义动画的具体内容。

animation0.interval,sometimes

“animation*”和“interval”这两行用于定义相应编号的动画何时开始执行。

“animation”后面的数字表示该动画定义的ID，即包含时间设置（interval）以及后续的“帧”设置（如pattern等）的一组配置。

动画ID可以使用任意编号，不一定要连续编号，但期望对相同含义的动画赋予相同的ID※。

之后的“sometimes”即为间隔定义的内容。

如例所示，当指定使用sometimes时，该动画会偶尔（每秒有二分之一的概率）自动播放。

也就是说，相当于指定了“ID为0号的动画会偶尔自动播放”。

关于还有哪些时间相关的指定方式，请参阅“Shell - surfaces.txt”中的动画间隔相关章节。

接下来，请逐一定义构成动画的每一张静止画面（帧）。

请按照pattern0、pattern1、pattern2的顺序依次填写。图案编号不得遗漏或重复。

请注意，在最前面务必加上同一动画组的ID（animation*）。

此外，interval定义行与一连串的pattern定义行请勿分开书写，应连续排列。

animation0.pattern0,overlay,100,50,0,0

overlay部分用于指定绘制方式。

overlay是一种将图像叠加在原始图像之上的绘制方式。

此外，还提供了多种其他的绘制方式。

有关详情，请参阅“Shell设置 - surfaces.txt”中的关于表面绘制方法的章节。

animation0.pattern0,overlayfast,100,50,0,0

其中100这一部分表示，在这一帧要绘制的是surface100。

基本上可以认为是指surface100.png。

如果设为101则会使用surface101.png这张图片。

若设为-1，则会停止该动画的绘制，并重置为显示基础图像（在上述示例中即surface0）。

animation0.pattern0,overlayfast,100,50,0,0

50这一部分表示显示时长（单位：毫秒）。

这是指定切换到该帧所需的时间。

请注意，这并不是该帧本身的显示时间。

animation0.pattern0,overlayfast,100,50,0,0

最后的0,0部分是帧的显示位置（x坐标，y坐标）。

指定从原始图像中偏移显示的幅度。

在x方向上，向右为正；在y方向上，向下为正。

※1

例如，假设角色有一个正面朝向的姿势对应的surface0，以及一个侧面朝向的姿势对应的surface5，那么希望在这两个姿势上都播放“眨眼”动画。

此时，除了像上面的例子那样在surface0上定义眨眼之外，还需要在surface5上进行类似的定义；但由于存在侧面朝向与正面朝向的区别，作为帧使用的表面（图像）理应不同。

然而，由于两者都被视为相同的“眨眼”动作，因此最好为其分配相同的动画ID（例如0）。

这一规则尤其在下文所述的“换装”情形中是必须遵守的。

编写surfaces.txt - element合成篇

element 是一种通过合成多张部件图像来将其作为单个表面进行处理的机制。

例如，如果必须将所有表面都以surface0.png这样的图像形式逐一准备，那么在增加角色表情时，哪怕只是嘴型稍有不同，也必须为每一种表情单独制作全身立绘。

然而，如果能够将身体部件与表情部件分开并进行合成，那么在增加表情数量时，只需为每种表情差异准备相应的图像即可，这样一来，整个资源包的容量将会大大减少。

此外，如果再将眼部和嘴部的部件分开，那么通过眼睛与嘴巴的不同组合就能呈现出多种表情，甚至无需实际绘制这些表情，也能生成相当丰富的表情效果。

以下是element定义的示例写法。

surface1
{
element0,overlay,body0.png,0,0
element1,overlay,face1.png,0,0
}

这样一来，就把“face1.png”叠加在“body0.png”之上，并将其定义为surface1。

可以根据需要，随意添加任意数量的待叠加部件。

另外，在这种情况下，surface1.png就不再需要了。

element0,overlay,body0.png,0,0

紧接在“element”之后的数字，是该表面上element的ID（顺序编号）。

ID是从0开始的连续编号。数字越小，表示该部件越靠下（更靠近画面深处）。

请注意，像surface*.png这样的PNG图像会被视为位于element0之下的部件。

element0,overlay,body0.png,0,0

接下来的关键字是绘图方法。

基本上与动画中的相同，但一些并非单纯进行图像合成的方法，如start和move等，将无法使用。

element0,overlay,body0.png,0,0

请指定连续合成的文件名。

可指定任意名称的PNG文件。

element0,overlay,body0.png,0,0

最后两个数字是合成位置的指定（x坐标，y坐标）。

用于指定相对于基础图像偏移多少进行合成。

在x方向上，向右为正；在y方向上，向下为正。

顺便说一下，在本次的例子中，与前面提到的碰撞判定与动画的例子不同，这里将元素的定义指定给了surface1，而不是surface0。

当然，这仅仅是一个示例性的说明，不过其中确实存在一定的原因※。

仅从Shell（人格）本身的行为来看，在surface0或10中使用element完全没有任何问题。

※2

例如，设想在类似人格数据库的Web服务中，想要显示人格的预览时。

如前所述，surface0和surface10被视为基本曲面，原则上不可省略。

也就是说，surface0和10可以视为必定存在的对象，因此用于预览时会比较方便。

然而，如果surface0和10是由element合成构成的，那么预览显示者就必须读取element定义，并按预期进行合成。

这无论是在人力操作中，还是在通过程序实现自动化的系统中，都会构成一定程度的障碍。

因此，如果考虑使用这类服务，或许最好将surface0和10以实体PNG图像的形式准备妥当。

此外，作为提供此类预览显示的服务，可以举出更新信息源「SiReFaSo」。

编写readme.txt

如果存在名为readme.txt的文件，它可以在所有者菜单或安装时等场合显示。

虽然可以省略，但如果Ghost的作者与Shell的作者不同，最好还是注明联系方式。

请填写Shell说明、联络事项等必要内容。

README也和其他文件一样，如果在第一行写上 charset,UTF-8 等，或者包含 BOM，则也可以使用 Shift JIS 以外的编码。

关于半透明表面

若要实现半透明效果，需创建一个与欲设为半透明的图像同名的“pna”文件。

比如surface0.png对应的文件就是surface0.pna。

在SSP的情况下，也可以为element合成的部件准备相应的文件。例如，针对face1.png，可以使用face1.pna这样的文件。

pna只是将用灰度表示透明度的PNG文件简单重命名而成。

在pna中，完全白色的部分会变为不透明，完全黑色的部分会变为透明，而介于两者之间的部分则会呈现半透明。

→ →
surface0.png surface0.pna 桌面显示

半透明的部分可作为角色进行点击。

因此，请将透明部分设置为纯黑色（RGB值为0,0,0）。

另外，在SSP情况下，无需使用pna，surface*.png图像可作为带有Alpha通道的PNG文件生成，并将该Alpha通道用作透明度。

在这种情况下，descript.txt中需要添加如下内容。

seriko.use_self_alpha,1

此外，关于如何制作带有Alpha通道的PNG文件，请参考各类绘图软件的相关说明（部分软件可能无法处理。您也可以尝试使用“带透明度的PNG”“32位PNG”“αPNG”等关键词进行搜索。

将多个表面的通用设置汇总

例如，当某个角色的姿态对应着多个表面时，可能会存在一些在碰撞检测、动画指定等方面完全相同的表面。

在这种情况下，除了在每个surface的breath中反复复制粘贴相同的设置之外，还有一些更为便捷的描述方法。

不过，其中绝大多数都是SSP限定的方法。

缩略图图像的设置

在店主菜单的Shell选项中，当鼠标悬停于某个Shell上时，可以显示缩略图。

例如当Shell较多、希望一目了然时，建议准备此项。

如果同一文件夹下存在名为thumbnail.png的图片，系统将自动使用该图片。
