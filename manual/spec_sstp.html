SSTP/1.x

参考：SSTP（外部链接）

目前，DirectSSTP在很大程度上依赖于Windows的系统规范，尚未考虑在其他操作系统上的实现。
由于IPC机制本身在其他操作系统中也普遍存在，因此建议另行制定相关规范。
一旦规范确定，我们将另行发布相关信息，请与Ukadoc Project联络

概要

SSTP是用于Ghost之间的通用通信协议。可用于简单的Sakura脚本执行，或接收来自外部的事件通知等。
通信基本基于TCP/IP进行。监听9801端口或9821端口（仅限SSP），按照SSTP协议发送请求后，将返回处理结果。
出于安全考虑，目前除非更改设置，否则仅限于在本地回环地址上监听，外部终端无法进行通信。此外，过去也曾监听11000端口，但由于曾被误认为是恶意软件的通信行为，现已予以废弃。
关于启动时临时指定监听目标的 --sstp-listen 等 SSP 启动选项，请参阅 SSP 帮助的启动选项。
IANA的端口号注册表中登记了7743和9801两个端口，但实际投入运行的只有9801端口。
与该缩写相同的还有微软为VPN通信制定的Secure Socket Tunneling Protocol，但两者在技术上并无关联。
未考虑对性能要求较高的频繁通信，也没有类似HTTP的keep-alive机制，每次通信结束后都会断开连接。

Direct SSTP

Direct SSTP是一种利用高度依赖于操作系统的IPC机制的通信规范。其协议规范与Socket SSTP相同，但旨在不使用相对较为繁重的TCP/IP协议，而是直接指定Ghost进行轻量级通信。
目前仅在Windows平台上确定了相关规范，具体如下。

WM_COPYDATA通过SendMessage系列函数发送（不可使用Post）
SendMessage中的hWnd = 通信目标人格的HWND 由FMO获取
wParam = 回复目标中“自身的”HWND。响应将通过指定了WM_COPYDATA的HWND（窗口）来接收。
lParam = COPYDATASTRUCT的指针
copydatastruct.lpData = 符合SSTP协议的字符串
copydatastruct.cbData = 字符串的长度
copydatastruct.dwData = 9801
备注：
为确保安全，发送方应在lpData中准备一个以零结尾的字符串，并建议在cbData中包含该零结尾字符。
并且接收方不应假定字符串以零结尾，而应始终根据cbData进行处理。
接收方应将作为通信目标指定的HWND视为与SSTP协议中指定的待接收人格相同，并尽可能优先处理该人格。
仅适用于收发双方均至少拥有一个窗口的GUI应用程序，控制台应用程序无法使用。

用同样的方法发送SAORI/1.0请求，也可以调用基础软件的内置模块。请参阅SAORI over DirectSSTP。[SSP 2.9.13]

SSTP over HTTP

SSTP over HTTP是一种极为简单的机制，它在SSP 2.6.32中实现，将SSTP请求原封不动地嵌入HTTP请求消息体，并将SSTP响应原封不动地返回到HTTP响应消息体中。
其设计初衷是供使用Electron等基于JavaScript开发的应用程序时，更便捷地进行SSTP通信之用。
请以HTTP/1.1协议，向localhost:9801（或另行指定的SSTP端口）的/api/sstp/v1发送Content-Type: text/plain的POST请求。
响应也将原样返回，采用HTTP/1.1 200 OK状态码，Content-Type: text/plain。
请注意，即使SSTP出现错误，HTTP仍返回200 OK。
此外，Content-Length头部是必需的，否则将返回错误。
支持HTTP的Keep-Alive功能。在HTTP/1.1中，默认情况下连接会保持，直到收到Connection: close 才会断开（HTTP/1.0则仅在显式指定Connection: keep-alive时才会保持）。对于带有Transfer-Encoding（如chunked等）的请求，连接不会被保持。此时，连接的保持完全由HTTP协议端的设置决定，消息体中的SSTP Connection头部将被忽略【SSP 2.9.03】。

试用

现有的js库可用于在JavaScript中实现基于HTTP的SSTP。

注意：如果Origin头部未指向localhost，则系统会强制将其视为来自远程地址的SSTP请求，从而对SakuraScript标签及可执行的SSTP方法施加严格限制，并且SecurityLevel头部也将被忽略。
此限制仅在HTTP的Origin为localhost且SSTP的SecurityLevel为local时才会被放宽。

keep-alive

从SSP 2.9.03起，（Socket）SSTP也像HTTP一样通过保活机制，可以在一条TCP连接上连续发送多个请求 [SSP 2.9.03]。
由于可以省去建立连接的步骤，因此特别适用于那些以较短间隔多次发送SSTP请求的客户端。

  • 在request中附加了 Connection: keep-alive 头时，连接才会被保持（与HTTP/1.0相同的显式指定方式）。如果不附加，则一如既往地在响应后断开连接，响应的内容也与以往相同。
  • 仅适用于SSTP/1.x版本。其他版本会忽略Connection头部，并始终断开连接。
  • Direct SSTP由于不存在连接概念，因此不在适用范围内。SSTP over HTTP则遵循HTTP端的保活规则（请参阅SSTP over HTTP）。
  • 如果request中包含Connection头部，则response中也一定会带有Connection头部。
    如果返回了Connection: keep-alive 和 Keep-Alive: timeout=秒数 ，则连接正在被保持。
    返回Connection: close 时，响应后将被断开连接（例如同时达到可维持连接数的上限等情况）。
  • 在保持连接的响应中，如果有附加数据，则必定带有Charset和Content-Length头部，且附加数据之后不会出现空行。如果没有附加数据，则以头部后的空行作为结束。
    此外，传统断开式响应末尾附带的零终止符（0x00）将不再发送。请仅根据空行和Content-Length来判断响应的结束。
  • 请在收到上一条response后再发送下一条request（不支持管道传输）。如果在收到response之前就发送下一条request，可能会导致连接被断开。
  • 请勿在request末尾附加空字符等多余字节，否则会被视为下一条request的一部分。
  • 在response之后，如果在Keep-Alive超时所指定的秒数内（SSP 2.9.03版本为5秒）没有收到下一次request，SSP端将主动断开连接。客户端应确保在任何情况下都能重新连接并重发。

request/response 请求/响应

与SHIORI等其他协议一样，这是一种仿照HTTP的自定义协议。
请求必须指定字符集，否则将返回错误，或按操作系统默认的字符编码进行解析。

  • 换行符为CR+LF。
  • 请求的末尾必须以空行结束（连同行首的换行符一起，即(CR+LF)×2）。
  • 在响应的末尾，对于EXECUTE等情形，可能会附加一些额外数据。在头部结束后插入一个空行，再接上附加数据，最后再加一个空行作为结束。若无附加数据，则可能仅以紧随头部后的那个空行作为结束。
  • 在带有附加数据的响应中，出于兼容性考虑，有时会完全不包含Charset头部，而仅返回附加数据。此时可假定其字符编码与请求端的字符编码相同。
  • 请求与响应的SSTP版本可能不同。请勿依据版本号进行解析。

各request方法共有的头部

关于特定方法的说明，请参阅后文各方法的单独介绍。

Charset 字符集
请求的字符编码。最好出现在第一行。
如果没有特别理由，建议使用UTF-8。
Sender 发件人
用于标识发送方的字符串，例如“SSTP发送工具”等。在使用COMMUNICATE方法时，为发送方的人格\0的名称。
SecurityLevel 安全等级
在SHIORI或Sakura脚本中处理时的安全级别指定，可选local或external。
仅对DirectSSTP，或像127.0.0.1这样明显来自本地的请求有效。
除来自localhost提供的html等资源外，SSTP over HTTP始终被视为external。
SecurityOrigin [SSP 2.6.59]
安全源 [SSP 2.6.59]
用于指示发送方服务器的类似URL的字符串。格式如下。HTTP头部的Origin字段的原理相同。
SecurityOrigin: null
SecurityOrigin: <scheme>://<hostname>
SecurityOrigin: <scheme>://<hostname>:<port>
scheme通常为http、https或sstp之一。hostname为发送方服务器的域名或IP地址，port为可接收响应的端口。
如无特别指定，则视为已指定为null。
通过HTTP的SSTP会始终设置HTTP的Origin头部内容，而SSTP内部的SecurityOrigin则被忽略。
Option 选项
指定在SSTP中执行的Sakura脚本的处理方式选项。
可使用逗号分隔进行多重指定。所指定的字符串如下。
nodescript : 禁用气泡中的SSTP显示（远程访问的SSTP也被禁用）
notranslate : 不执行OnTranslate或MAKOTO中的翻译处理
nobreak : 不中断当前正在执行的脚本，直至其执行完毕 strict：将SakuraScript解析失败的部位记录到错误日志中。适用范围包括：指定不存在的表面（\s）、动画（\i）、气球（\b），以及未知标签、\![命令]、\&[实体引用]，还有必要的[]或数字缺失，以及\p、\b、 、\c、\q的非法值。此选项对SEND脚本及NOTIFY/GIVE中人格返回的脚本有效【SSP 2.8.94】
ID
被称为“Owned SSTP”的东西。是指当指定了通过SHIORI uniqueid发送的 ID 或FMO 识别 ID（仅限 SSP）时，将忽略各种安全检查及锁定等限制，使该 SSTP 以与人格内部处理相同的优先级被处理。
SecurityLevel被指定为local，并且即使处于 等禁止中断的状态下，也能够强制进行中断播放。
X-SSTP-PassThru-(任意字符串)
在NOTIFY等与人格端通信时，直接传递给SHIORI的头部。
仅进行文字编码转换等最低限度的处理，(任意字符串)的部分及其内容将原样中转。
HWnd
仅限DirectSSTP，用于指示应返回响应的窗口句柄。
将窗口句柄（相当于指针）的数据视为无符号十进制整数，并将其转换为字符串。
省略时为WM_COMMUNICATE的wParam。
ReceiverGhostHWnd [SSP 2.5.57]
仅限于(Socket)SSTP，表示应发送请求的人格的\0的窗口句柄。
指定此项后，待处理的人格将被固定，即使通过Socket也能实现与DirectSSTP相同的处理。
若未找到，则立即以404 Not Found错误终止。
ReceiverGhostName [SSP 2.5.57]
（仅限Socket）SSTP专用，用于指示应发送request的人格的\0名称。
指定此项后，待处理的人格将被固定，通过Socket也能实现与DirectSSTP相同的处理。HWnd的名称版本。
若未找到，则立即以404 Not Found错误终止。

response的状态码

与HTTP相同，200开头表示正常受理，其余为错误。

200 OK
正常结束（有返回值）
204 No Content
正常结束（无返回值）
210 Break
已执行，但在脚本运行过程中被中断
※仅在极少数情况下，如带有Entry的SEND/1.x等，通常会立即返回200或204。
400 Bad Request
请求存在某些无法完全覆盖的缺陷
404 Not Found ※仅限SSP
在指定人格的SSTP中，该人格未被安装或启动
408 Request Timeout
超时：例如与人格/SHIORI端无法通信时（平时几乎不会发生）
409 Conflict
处于禁止中断状态（如\t标签等），或正在处理其他请求
413 Payload Too Large ※仅限SSP
SSTP请求过长，已被拒绝处理
420 Refuse
因Ghost端的配置原因而被拒绝接收
500 Internal Server Error ※仅限SSP
由于处理系统内部检测到的某种问题而无法完成处理
501 Not Implemented
包含未实现的命令等，导致无法处理
503 Service Unavailable
由于处理系统内部原因，无法接受SSTP
505 Version Not Supported ※仅限SSP
SSTP版本异常（如低于1.0或高于3.0等）
512 Invisible
由于最小化等原因，未显示任何人格，处于无法进行任何操作的状态

方法：NOTIFY

这是一种用于向人格发送事件通知的方法。
SEND与NOTIFY被视为同一处理，功能上并无差异。有关共通头部的详细信息以及IfGhost的分发规则等规范，请参阅方法：SEND。
Event头部对应SHIORI/3.0 ID，Reference*将原样传递。

仅事件通知示例(NOTIFY/1.0)

NOTIFY SSTP/1.0
Charset: UTF-8
Sender: Media Player
Event: OnMusicPlay
Reference0: 自由の翼
Reference1: Linked Horizon

当人格方指定的事件ID未被响应时，可以指定并播放一段“备用”脚本。
此时，若指定了IfGhost头部，则其后的Script头部将被视为专属于该人格的脚本。

带备用响应的示例(NOTIFY/1.1)

NOTIFY SSTP/1.1
Charset: UTF-8
Sender: Media Player
Event: OnMusicPlay
Reference0: 紅蓮の弓矢
Reference1: Linked Horizon
IfGhost: Emily,Teddy
Script: \0\s[6]那天，艾米莉想起来了…\n\s[7]今天还没有吃红薯！\1\s[11]わざ特意现在想起来了吗？
IfGhost: ラーシェ,ティセ
Script: \0\s[3]虽说叫巨人，身高也不过几节车厢那么长吧。\1\s[14]不过要是它竖立起来，那确实会觉得很大呢。

方法：SEND

SEND是用于从外部应用向人格发送Sakura脚本和SHIORI事件并使其执行的方法。
SEND 与 NOTIFY 被视为相同的处理方式，两者在功能上并无差异。以下说明同样适用于 NOTIFY。
既可以使用 Script 头部直接指定 Sakura脚本，也可以通过 Event 头部发送事件，并在 SHIORI 的响应中获取脚本。
Event与Script可以同时使用；当针对Event的SHIORI响应未返回任何脚本时，将回退至Script头部所指定的脚本。
若未指定目标人格，则以当前正在运行的人格为目标。

Sender: SampleApp

request专有头部

Sender 发件人
虽是通用头部，但作为SEND/NOTIFY中的特殊值，可使用Sender: First。指定后，将以首次启动时的人格（さくら）为对象。
当Sender和User-Agent均未指定时，将返回400 Bad Request错误。
Script 脚本
要执行的Sakura脚本。
与Event头部配合使用时，当针对Event的SHIORI响应未返回脚本时，用作后备方案。
Entry 条目
输入数据。传递给SHIORI。
Event 事件
SHIORI事件名。在SHIORI/3.0中，被视为ID头部的指定。
Reference* 参考*
事件的Reference头部。SHIORI会对字符编码等进行最低限度的处理后原样传递。
IfGhost
以\0侧名,\1侧名的格式指定人格名称时，紧随其后的Script头部将被视为特定人格专用。
如果在IfGhost之后不存在Script头部，则该Script将作为不属于IfGhost情况下的默认处理脚本。

详细的分配规则请参阅下文的由IfGhost进行的脚本分配。
Ghost 人格
通过人格名称（descript.txt中的name）指定目标人格。
Option
指定SSTP下运行的Sakura脚本的处理方式选项。
可使用逗号分隔进行多项指定。除通用选项（nodescript、notranslate等）外，SEND/NOTIFY可用的选项标志如下。
nobreak : 在不中断当前正在播放的脚本的情况下将其加入队列。
notify : 以notify模式（无需响应）发送SHIORI事件。此外，当脚本在ValueNotify头部被返回时也会被强制按相同方式处理。[SSP 2.6.76]

SHIORI响应中包含的头部将被透传。

由IfGhost进行的脚本分配

通过多次编写IfGhost头部，并将其与相应的Script头部相结合，可以为每个人格指定不同的脚本。
IfGhost和Script按照出现顺序进行对应。在第一个IfGhost之前描述的Script是默认脚本。

名称匹配
当IfGhost为“\0侧名,\1侧名”格式时，必须两个名称都匹配。
当IfGhost仅为“\0侧名”时，仅需\0侧名匹配即可被选中。
如果均不匹配，则使用默认脚本。但若人格端设置了“未指定SSTP拒绝”，则连默认脚本也不会被使用。
默认人格处理
以下名称将被视为默认人格（さくら），其脚本也将作为默认脚本运行。
「さくら」「エミリ」「えみりぃ」

方法：COMMUNICATE

通过COMMUNICATE方法，您可以从外部向人格传递任意字符串，使其作出响应。
这基本上与人格内部使用通信框进行响应的方式相同，但由于是SSTP协议，有时可能会被人格端拒绝接收。

简单的COMMUNICATE(COMMUNICATE/1.1)

COMMUNICATE SSTP/1.1
Charset: UTF-8
Sender: User
Sentence: 早上好。

通信可以在SSTP服务器之间（即Ghost之间）反复进行收发。
在SHIORI/3.0的响应Reference0中进行发送时，SSTP的发送时机为Sakura脚本执行完毕之时。
利用这一点，可以实现让同时启动的多个Ghost彼此对话的效果。

人格间沟通(COMMUNICATE/1.2)

COMMUNICATE SSTP/1.2
Charset: UTF-8
Sender: Emily
HWnd: 28236
Sentence: \0\s[5]Ciallaan～！我是艾米莉！\n我的肚子还有一点空间…？\1\s[11]你要是这么说的话，又会胖的哦？
Surface: 5,11
Reference0: 给我红薯
Reference1: 给我多来点
Reference2: 现在就给我

request固有头部

Reference* 参考*
通信的扩展信息。在SHIORI/3.0中，该信息存储于Reference2及之后的版本中。SSTP Reference0 = SHIORI Reference2
Surface 表面
发送源人格在进行通信发送时（≈脚本执行结束时）的\0和\1的表面编号。
在OnCommunicate事件中作为Surface头部传递。
Option 设置
[旧规格]指定substitute后，Sentence的内容将由\1来朗读。※SSP尚未实现

方法：EXECUTE

通过EXECUTE方法，可以获取人格的各项信息，以及执行不依赖Sakura脚本的各种命令。
执行此方法时，人格不会说话，但其内部状态可能会被改写

EXECUTE示例

EXECUTE SSTP/1.1
Charset: UTF-8
Sender: SSTPクライアント
Command: GetName

request固有头部

Command 或 Command[参数1,参数2...]
应执行的命令。其执行内容及返回信息将在后文详述。
方括号之后用于指定传递给该命令的参数。
Reference* [SSP]
也可以使用Reference0～等头部来指定参数，而无需使用方括号表示法。

有关Command头部可指定的字符串以及response中“附加数据”所返回的结果，请参阅下文。

GetNames [SSP]

GetFMO [SSP 2.5.57] [有远程限制]

但仅限于通过SSTP进行通信的应用程序内部的管理部分，这与原本供多个并发应用程序共享的FMO有所不同。
主要用于那些不带窗口、无法发送Direct SSTP的控制台应用程序等场合，通过仅使用Socket SSTP并配合ReceiverGhostHWnd头部，以实现相当于Direct SSTP的功能。
以换行符分隔，以空行结尾。

Quiet [无法远程]
保持沉默，直到16秒钟后或执行了Restore。无附加数据（状态码为200系列时表示成功）
Restore
解除Quiet模式。无新增数据（状态码为200系列时表示成功）
CompressArchive [SSP 2.7.23] [无法远程]
将指定文件夹中的所有文件压缩成一个ZIP文件。
参数0：压缩文件名（需指定完整路径，不可使用相对路径）
参数1：待压缩文件夹的完整路径
参数2及以后：可选参数（可省略）
可选参数如下。
--event=事件标识符……指定事件标识符后，响应结束后将继续压缩，完成后触发相应事件。若标识符以On开头，则触发该标识符对应的事件；否则将触发OnCompressArchiveComplete或OnCompressArchiveFailure事件。若省略此参数，则在处理完成前不会返回响应。
--password=密码……使用指定的密码启用AES加密ZIP。
有关操作后事件的规范，请参阅OnCompressArchiveComplete・OnCompressArchiveFailure。
[SSP 2.9.25] 从 SAORI over DirectSSTP 中，也可以通过internal_file的CompressArchive来调用（也可以使用相对路径指定和 / 分隔符）。
从安全角度考虑，压缩目标仅限于解压到SSP管理下的文件夹（如ghost文件夹、balloon文件夹等，在“文件夹”设置中指定的位置）内。
此外，由于该限制可能会随时加强，因此最好将其限定在Ghost自身数据所在的文件夹之下。
无附加数据（状态码为200系列时表示成功）
ExtractArchive [SSP 2.7.23] [无法远程]
解压指定的ZIP文件。
参数0：压缩文件名（需指定完整路径，不可使用相对路径）
参数1：解压目标文件夹的完整路径
参数2及以后：可选参数（可省略）
可选参数如下。
--event=事件标识符……指定事件标识符后，响应结束后将继续解压，解压完成后将触发相应事件。若标识符以On开头，则触发该标识符对应的事件；否则将触发OnExtractArchiveComplete或OnExtractArchiveFailure事件。若省略此参数，则在处理完成前不会返回响应。
--password=密码……使用指定的密码进行解压，无需提示输入密码。
有关操作后事件的规范，请参阅OnExtractArchiveComplete・OnExtractArchiveFailure。
[SSP 2.9.25] 从 SAORI over DirectSSTP 中，也可以通过internal_file的ExtractArchive来调用（也可以使用相对路径指定和 / 分隔符）。
从安全角度出发，解压目标仅限于SSP管理下的文件夹（如ghost文件夹、balloon文件夹等，在“文件夹”设置中指定的位置）内。
此外，由于该限制可能会随时加强，因此最好将其限定在Ghost自身数据所在的文件夹之下。
无附加数据（状态码为200系列时表示成功）
DumpSurface [SSP 2.5.98] [无法远程]
将已合成的表面图像输出到指定目录。参数与\![execute,dumpsurface]相同。
但是无法指定事件ID，需按目录、作用域ID、表面列表、prefix、零位置截取、动画ID [SSP 2.9.05] 的顺序指定。
[SSP 2.9.08] 与 SakuraScript 版相同，也可以以 --dir= / --scope= / --surface= / --prefix= / --fromzero= / --animation= 的形式不分顺序地指定，并且可以与按上述顺序的指定混用（不以 -- 开头的参数，按出现顺序以上述顺序分配）。除目录以外都可以省略，省略 作用域ID 时为 0。--event= 会被忽略。

方法：GIVE

[旧规格] 这是一种用于向人格赋予各类数据并对其进行处理或触发反应的方法。
这已是相当老旧的规格，目前已无使用价值。请改用NOTIFY或COMMUNICATE。

request示例

GIVE SSTP/1.1
Charset: UTF-8
Sender: SSTPクライアント
Document: 先放水，然后是面粉。


GIVE SSTP/1.1
Charset: UTF-8
Sender: SSTPクライアント
Song: 佐世保の時雨

request固有头部

Document
文档（通用字符串）
在SHIORI/3.0中，它将被视为与用户通信相同，并触发OnCommunicate事件。
Song
歌曲名称。
在SHIORI/3.0中，会触发OnMusicPlay事件，且Reference0将变为Song头部所指定的字符串。
