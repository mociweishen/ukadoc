DLL通用规范

本规范定义了SHIORI、SAORI及其他伪春菜系统所使用的DLL模块的通用接口。

内存管理

所有参数与返回值的传递均通过Windows的Global Memory (全局内存)进行。具体而言，按照以下步骤处理：

  • 基础软件使用GlobalAlloc()函数并指定GMEM_FIXED标志来申请内存，然后将数据写入其中
  • 模块将接收到的HGLOBAL强制转换为(char*)，并直接访问数据
  • 模块通过引用 len 参数获取数据长度，并读取所需数据
  • 模块使用 GlobalFree() 释放内存
  • 在返回处理结果时，模块会通过GlobalAlloc()函数新申请一块指定为GMEM_FIXED类型的内存
  • 模块将结果写入所分配的内存，并在len中设置新的数据长度
  • 基础软件会在使用完返回的内存句柄后，通过 GlobalFree() 来释放它。

注意点：

  • 使用GMEM_FIXED标志时，无需调用GlobalLock()/GlobalUnlock()函数
  • 可通过将 HGLOBAL 强制转换为 (char*) 来直接访问内存
  • 由于传入的内存不保证以NULL结尾，因此务必通过len参数来限制访问范围
  • 为返回值分配的内存应比len多预留1字节并进行零终止，以确保在任何基础软件实现下都能稳定运行

request 函数

extern "C" __declspec(dllexport) HGLOBAL __cdecl request(HGLOBAL h, long *len);

所有请求均通过唯一的request函数进行。request函数是伪春菜模块的主要接口，负责处理来自基板的所有请求。

请求数据的格式参考了HTTP和SSTP的头部格式设计，并遵循以下规则：

  • 所有行均以CR+LF（0x0D, 0x0A）分隔
  • 第一行应写明命令名称和协议版本
  • 从第二行起，可按“头部名：值”的格式添加任意数量的头部
  • 通过连续放置两个CR+LF来表示头字段部分的结束（即空行）
  • 字符编码遵从头部指定的方式（通常为UTF-8或默认的OEM代码页）

生命周期函数

在DLL加载和卸载时，以下函数会被调用。

loadu函数

extern "C" __declspec(dllexport) BOOL __cdecl loadu(HGLOBAL h, long len);

用于执行模块初始化的函数。
第一个参数的全局内存中存储的是模块的目录路径，采用。UTF-8编码。

自SSP 2.6.92（2025年1月16日）起已实现。在此之前仅支持load功能。

处理内容示例：

  • 将传入的路径设为当前目录，并读取所需的数据文件。
  • 初始化模块运行所需的资源
  • 根据需要对日志文件和数据库进行初始化

注意点：

  • 即使字符串数据不再需要，也必须释放所分配的全局内存
  • 初始化成功时返回 TRUE，失败时返回 FALSE
  • 本函数由基础软件优先调用

load函数

extern "C" __declspec(dllexport) BOOL __cdecl load(HGLOBAL h, long len);

loadu 函数的旧版本。
除非第一个参数的模块目录路径是以默认的OEM代码页（在日语环境下为CP932）编码的，否则其行为与loadu函数相同。

注意点：

  • 用作loadu函数未实现时的回退方案
  • 为确保兼容性，应同时实现load和loadu两个函数；当已通过loadu完成初始化时，若又调用了load，则宜予以忽略。
  • 为支持Unicode，需将接收到的路径正确转换为宽字符字符串

unload函数

extern "C" __declspec(dllexport) BOOL __cdecl unload();

用于执行模块终止处理的函数。在卸载模块时由基础软件调用。

应实现的处理：

  • 释放通过CreateFile等打开的文件句柄
  • 释放通过CreateMutex等创建的同步对象
  • 等待通过 CreateThread 等创建的线程结束，并执行后续处理
  • 此外，释放模块所申请的所有系统资源

返回值目前尚未使用，但出于对未来扩展性的考虑，建议返回 TRUE。
