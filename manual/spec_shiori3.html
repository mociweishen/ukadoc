实现对应状态的检测

关于扩展头部的实现支持情况，会在SHIORI执行初期通过ID: capability进行通知。

request 请求

示例

GET SHIORI/3.0
Charset: UTF-8
Sender: SSP
SenderType: internal,raise
SecurityLevel: local
Status: choosing,balloon(0=0)
ID: OnFirstBoot
BaseID: OnBoot
Reference0: 1

※换行符为CR+LF。
※最后必须以空行结束（与前一行末尾一起构成(CR+LF)x2）。

方法
GET
以在响应的Value头部返回某些内容为前提的方法。
NOTIFY
以不返回任何值为前提的方法。响应的Value头部将被忽略。
主要用于因某种模式限制而处于“无法说话”状态时，或在刚启动后的状态通知事件中使用。
请注意，同一个ID（事件名）有时会同时用于GET和NOTIFY。
Charset 字符集

字符代码。最好在第一行或至少字符代码在ASCII范围以外的行之前。

Sender 发送者

事件发送方。

SenderType 发送方类型[SSP 2.5.05～扩展]

事件发送方的属性。如下所示。如有多个，请用逗号连接。
对于ID：OnTranslate，将继承翻译源事件的属性。

internal
来自应用程序内部的事件。
external
来自应用程序外部的事件。
sakuraapi
由Sakura API触发的事件。
embed 嵌入
由\![embed]标签触发的事件。
raise 引发
由\![raise]标签触发的事件。
property
由属性系统引用指令触发的事件。
plugin
由插件触发的事件。
sstp
SSTP所引发的事件。
communicate
由通信规范所引发的事件。
SecurityLevel 安全级别

脚本执行时的安全级别。以下之一。
对于ID：OnTranslate，将继承翻译源事件的属性。
尽可能在最前面的几行中发出通知。至少应在ID头部之前出现。

local
来自正在运行的终端的通知。
external
运行中终端外部发出的通知。

在external的情况下，由于是来自执行中机器的外部的通知，所以在安全性上需要注意处理。
SenderType中的internal/external是一个与之不同的概念；即使事件是由应用程序外部触发的，只要被认定为安全，仍会被判定为local。因此，即便SenderType为external，SecurityLevel也可能为local。

SecurityOrigin 安全来源[SSP扩展]

用于指示发送方服务器的类似URL的字符串。格式如下。与HTTP头部的Origin字段的原理相同。
SecurityOrigin: null
SecurityOrigin: <scheme>://<hostname>
SecurityOrigin: <scheme>://<hostname>:<port>
scheme通常为http、https或sstp之一。hostname为发送方服务器的域名或IP地址，port为可接收响应的端口。
在SSTP等协议中，若未指定头部，或根本不存在发送源的概念等情况下，无信息时将返回null。
同时请参考SSTP规范中的SecurityOrigin。

Status 状态[SSP扩展]

人格的运行状态。如下所示。若有多个，则以逗号分隔。

talking
正在说话中
choosing
选项显示中
minimizing
正在最小化中
induction 归纳
在\![enter,inductionmode]中
passive 被动
在\![enter,passivemode]中
timecritical
在时间关键区段(\t)中
nouserbreak
不允许换行
在\![enter,nouserbreak]中

online
正在进行网络通信
opening(类型)
输入框等已打开。
若同时打开了多种类型，则以“/”分隔并列举。
“dialog”指文件选择、颜色拾取等。
例如：opening(communicate/input/teach/dialog)
balloon(ID列表)
气球处于显示状态。
以“角色ID=气球ID”的形式列举。
若同时开启多个，则以“/”分隔列举。
例如：balloon(0=2/1=0) 表示\0为大型气球，\1为普通气球。
ID

事件名或文本资源的标识符。

BaseID [SSP扩展]

可兼容的基本事件名。
例如：OnFirstBoot与OnBoot兼容，且OnFirstBoot是OnBoot的子类型，因此OnFirstBoot的BaseID中会包含OnBoot。

Reference*

与事件相关的附加信息集合。Reference后可接数字。可输入的行数无限制（只要内存允许）

X-SSTP-PassThru-(任意字符串) [SSP 2.5.05～扩展]

仅当从SSTP收到事件通知时，SSTP请求头中以"X-SSTP-PassThru-"开头的字段才会原样被通知。
在非SSTP情况下则不会被添加。

response 响应

示例

SHIORI/3.0 200 OK
Charset: UTF-8
Sender: AYA
Value: \1\s[10]\0\s[0]\e

※换行符为CR+LF。
※最后必须以空行结束（与前一行末尾一起构成(CR+LF)x2）。

状态码

HTTPと同じく、200番台が成功、ほかはなにかしらの失敗（エラー）を示す。
現在主に使用されているのは下記の通り。

200
200 OK
成功，有返回值（Value）。
204
204 No Content
成功，无返回值。
311
311 Not Enough
在ID:OnTeach（SHIORI/2系的TEACH方法）中，表示需要进一步的追加信息。
再次打开输入框并向用户进行询问，待用户输入完成后，添加包含输入字符串的Reference。
312
312 Advice
ID：在OnTeach（SHIORI/2系的TEACH方法）中，表示最近输入的字符串因无法解析而应被丢弃。
首先销毁最后一个Reference，然后重新打开输入框并询问用户，待用户输入完成后，再添加包含该输入字符串的Reference。
400
400 Bad Request
请求字符串无法解析。
500
500 Internal Server Error
SHIORI 内部发生了某种错误，无法返回响应。
Charset 字符集

字符代码。最好在第一行或至少字符代码在ASCII范围以外的行之前。

Sender 发送者

发送者。通常为 SHIORI 的名称。

Value 值

想要表达的脚本内容。

ValueNotify [SSP扩展 2.5.35]

[实验性功能]
即使请求方法为NOTIFY，也用于执行Sakura脚本的扩展功能。
当通过此头部返回Sakura脚本时，将立即执行。而在GET请求中，则会在执行Value头部中的脚本之前先执行。
可执行的标签极为有限，其他标签及任何其他字符串均将被忽略。
当方法不是NOTIFY，或Value头部已存在时，该头部将被忽略。 在2.6.76版本中已取消此限制
当前可执行的标签如下：

  • \![sound]
  • \![set,trayicon]
  • \![set,trayballoon]
  • \![raise]
  • \![raiseother]
  • \![raiseplugin]
  • \![timerraiseother]
  • \![timerraiseplugin]
  • \![notify]
  • \![notifyother]
  • \![notifyplugin]
  • \![get,property] ＋2.6.82
  • \![set,property] ＋2.6.82
SecurityLevel 安全级别[SSP扩展]

以下任一选项。

local
相当于在当前设备内部运行的脚本的安全级别。
external
相当于从当前设备外部运行的脚本的安全级别。

想要运行的脚本的SecurityLevel。当设置为external时，部分脚本会因安全机制而无法执行。

Marker 标记[SSP扩展]

要在balloon标记（balloon下方的附加信息）中显示的字符串。

ErrorLevel [SSP扩展]

SHIORI内部发生的错误级别。取值如下之一。若需表示多个错误，请以字节值1分隔。

info
信息。不属于错误。
notice
通知。虽难称之为错误，但应予修正的表述等。
warning
警告。存在书写错误等情况，处理尚未停止，但建议予以纠正。
error
常规错误。由于拼写错误等原因，某些处理被中断且无法恢复。
critical
致命错误。比error更严重，应立即采取相应措施。

如果存在此头部，则会通知用户发生了某种错误。
可由用户自行设置通知级别，通常为error及以上。
对于SSP而言，错误会被记录到错误日志中，并且错误图标会显示在通知区域。

ErrorDescription 错误描述[SSP扩展]

SHIORI内部发生的错误的详细信息。仅在存在ErrorLevel时有效。
当需要表示多个错误时，以字节值1作为分隔符。
ErrorLevel与ErrorDescription的元素数量必须相同。

BalloonOffset [SSP扩展]

气球的偏移值（X,Y）。

Reference0

若要发送通信，请填写人格\0侧的名称。

Reference1～

通信的附加信息。
响应中的Reference1＝SSTP Communicate的Reference0＝接收方的OnCommunicate的Reference2
请注意，由于兼容性问题，可能会出现如上所示的偏差。

Age [SSP扩展]

沟通的代数。首次为零，每进行一次互动则加1。
虽然是SSP扩展，但实质上是SHIORI/2.x的兼容处理。

MarkerSend [SSP扩展]

在通信过程中希望“显示在对方一侧”的气泡标记字符串。
作为SSTP的Marker头进行发送。

X-SSTP-PassThru-(任意字符串) [SSP 2.5.03～扩展]

仅在SSTP收到事件通知时，此头部才会原封不动地附加到SSTP的响应中。
其他情况下将被忽略。
可指定多个头部，但若需返回多个头部，请更改头部名称。
（旧头部名：X-SSTP-Return- 将予定废止）
