FMO/Mutex

参考：内存对象（外部链接）

目前，本规范在很大程度上依赖于Windows的实现，尚未考虑在其他操作系统上的部署。
由于共享内存和Mutex本身在其他操作系统中也普遍存在，因此建议另行制定相关规范。
一旦规范确定，我们将另行发布相关信息，请通过Ukadoc Project与我们联系。

Mutex 互斥量

为表明基础软件正在运行，SSP持有名为"ssp"的互斥量，而Materia和CROW则持有名为"sakura"的互斥量。
通过确认该命名互斥量的存在，可以低成本地判断系统是否处于启动状态。
Mutex自身的状态并未固定，无需检查其是否处于信号状态。

仅用于判断是否存在时的代码示例（C++）

HANDLE hmutex = OpenMutex(MUTEX_ALL_ACCESS,FALSE,"ssp");
if ( hmutex ) {
  // 存在
  CloseHandle(hmutex);
}
else {
  //不存在
}

FMO (File Mapping Object 文件映射对象)

所有基础软件在运行时都持有命名的文件映射对象（FMO）。
通过读取这种进程间共享内存，可以以相对较低的成本获取正在运行的人格进程。
为避免读取到写入过程中的不完整信息，已采用FMO用Mutex进行互斥控制。请一并确认。

FMO的名称与字符编码

Sakura：依赖操作系统，在日语操作系统下为Shift JIS
SakuraUnicode : 固定使用UTF-8 [SSP 2.5.26之后～]

FMO的大小

前4个字节（第0至第3字节）表示已分配的FMO大小。
こ这并非所写入信息的长度，而只是FMO本身所分配的固定大小。
目前该值采用小端序，为0x00010000，即固定64KB。
为确保与其它程序的兼容性，目前暂不考虑调整该大小。

数据主体

从第4字节开始即为FMO的数据主体，其格式如下。
(32字节的识别ID).(键名)[\1]值[\r\n]
\1]表示字节值1，[\r\n]表示CR+LF（换行）。
该格式将按多行重复。

数据结束

数据结束符与C语言字符串相同，均为字节值0。
因此，数据主体所能使用的最大尺寸为65531字节（65536 - 4 - 1）。
F如果需要向FMO写入数据，且可能超出大小限制时，请注意避免写入不完整的信息。
当预计会超出大小限制时，最好避免一次性写入整组数据；即使无法做到，也请确保不会在某一行的中间位置中断。

32字节的识别ID

用于标识一组人格的唯一识别ID。至少在FMO内部，必须选择与其他ID不重复的字符串。
通常会将某些唯一信息进行组合后计算MD5哈希值，或者结合HWND（窗口句柄）来生成。
在Materia规范中并未规定长度，但为保证兼容性，应采用固定长度32字节。

键名·值

用于指示信息类型的键与信息主体。具体如下。

path
正在运行的基软件的根目录完整路径。
hwnd
主窗口的窗口句柄。采用十进制表示。
name
与descript.txt中的sakura.name相同。
keroname
与descript.txt中的kero.name相同。
sakura.surface
\0侧当前显示的表面ID，十进制表示。
kero.surface
\1侧当前显示的表面ID，十进制表示。
kerohwnd
\\1侧窗口的窗口句柄。十进制表示。[仅限SSP]
hwndlist
以逗号分隔列出当前正在使用的所有窗口句柄。采用十进制表示。[仅限SSP]
ghostpath
启动中人格的完整路径。[仅限SSP]
fullname
启动中的Ghost的descript.txt文件中的name条目。[SSP 2.5.58之后]
modulestate
由正在运行的人格加载的模块组状态，以逗号分隔的字符串。[SSP 2.5.79～]
shiori:running SHIORI已加载（未加载时该字符串本身不存在）
makoto-ghost:running 人格端的MAKOTO已加载
makoto-shell:running Shell端的MAKOTO已加载
compatible:running 已切换至兼容模式，且script.txt等文件已加载
当SSP与各模块组之间的通信出现异常时，将用critical替代running
示例： ssp_fmo_header_00004468_00120da6.modulestate[\1]shiori:running,makoto-ghost:running\r\n

FMO用Mutex

FMO本身不具备互斥机制，因此为避免读写冲突，需另行持有Mutex。
FMO的名称将变为“FMO名+FMO”，例如如下所示。
FMO = Sakura : Mutex = SakuraFMO
FMO = SakuraUnicode : Mutex = SakuraUnicodeFMO
此处信号状态与非信号状态的判定至关重要。
进行读写操作时，务必使用WaitForSingleObject或同等的等待函数获取所有权，操作结束后再通过ReleaseMutex释放所有权。

由于旧版基础软件等可能不支持FMO用互斥锁，因此即使获取互斥锁失败，也请不要将其视为错误。
不过在这种情况下，请务必注意编写尽可能安全的代码，以避免在不完全写入时获取到FMO。

用于读写FMO的C++代码示例

//基础软件等需要保持的应用程序，改用CreateMutex
HANDLE hMutex = OpenMutex(MUTEX_ALL_ACCESS,FALSE,"SakuraFMO");

//有些基础软件不支持FMO用Mutex，所以如果没找到就简单地跳过
bool isWaitSuccess = true;

if ( hMutex ) {

    //如果用INFINITE等待的话会永远等下去导致GUI卡死，请根据情况适当调整
    DWORD result = WaitForSingleObject(hMutex,INFINITE);
    
    if ( result != WAIT_OBJECT_0 ) {
        isWaitSuccess = false;
    }
}

if ( isWaitSuccess ) {

    //需要保持的应用程序改用CreateMutex
    HANDLE hFMO = OpenFileMapping(FILE_MAP_ALL_ACCESS,FALSE,"Sakura");

    if ( hFMO ) {

        char *pDataStart = static_cast<char*>(MapViewOfFile(hFMO,FILE_MAP_ALL_ACCESS,0,0,0));

        if ( pDataStart ) {

            //开头的4字节是FMO最大尺寸。
            // 注意这与字符串终止符（C语言字符串的零终止）不同。
            unsigned long length = *reinterpret_cast<unsigned long*>(pDataStart);

            char *pData = pDataStart;
            pData += 4;

            //****************************************
            //在这里使用pData和length进行某种处理
            //****************************************

            //解除MapViewOfFile的映射
            UnmapViewOfFile(pDataStart);
        }
            
        //释放FMO句柄
        //基础软件等需要保持的应用程序不要释放，要持续持有
        CloseHandle(hFMO);
    }
}

if ( hMutex ) {
    if ( isWaitSuccess ) {
    
        //WaitForSingleObject会使Mutex变为非信号状态，所以要恢复到信号状态（Release）
        ReleaseMutex(hMutex);
    }

    //最后也不需要Mutex的句柄了，所以释放
    //基础软件等需要保持的应用程序不要释放，要持续持有
    CloseHandle(hMutex);
}
