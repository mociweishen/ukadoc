install.txt

install.txt

概要

也请参考文件结构「安装」的页面。

人格、Balloon、Shell等各类伺か/SSP内容的安装配置文件。
所有压缩包均可解压后手动安装，但若存在经过正确设置的install.txt文件，则会启用安装程序功能，从而可通过拖放等简便方式完成安装。

示例与基本写法

对于人格的情况（Balloon和插件也只需更改type部分，几乎相同）

charset,UTF-8
name,凡例さん
type,ghost
directory,example

对于附加Shell的情况

charset,UTF-8
name,凡例さん终极形态
type,shell
directory,ultimate
accept,凡例さん

对于人格的补充（附加文件）的情况

charset,UTF-8
name,凡例さん猫化补丁
type,supplement
accept,凡例さん

将Balloon随人格一同打包时

charset,UTF-8
name,凡例さん
type,ghost
directory,example
balloon.directory,example_balloon
balloon.source.directory,balloon

※仅适用于SSP，作为多实例安装包时置于最顶层
（随附的各组件中的install.txt可按常规方式编写）

charset,Shift_JIS
name,凡例さん家族一次性入住套餐
type,package

charset的指定必须位于第一行（若为Shift_JIS可省略）。

name、type为必填项。directory在type非supplement或package时也为必填项。
其他各项可根据需要进行指定。

在追加Shell或插件的情况下，为避免被意外的人格程序安装，可以使用accept指定。
尤其是补充，由于存在意外覆盖导致文件损坏的风险，几乎不可或缺。
请注意，用于accept指定的是本体侧名，而非人格名称。

在SSP中，若要将Balloon或插件与人格或Shell一同打包，则需使用*.directory。

此外，name主要用于安装类SHIORI Event的Reference的通知内容中
某些人格可能会利用这一信息，在安装完成后立即对目标进行切换；但如果descript.txt中记载的实际人工名称与install.txt中的表述不一致，则该切换功能将无法正常生效，请务必注意。

charset,字符编码

要显示的字符编码。为考虑与旧版环境的兼容性，建议使用Shift_JIS；其他情况则推荐使用UTF-8。

（操作系统默认设置或SSP→国际化→缩略时的字符编码→文本定义）

name,对象名

该对象的名称。

不可省略

type,种类

该对象的名称。

ghost
人格
shell
添加到人格的Shell
supplement
添加到人格的文件
balloon
气球
plugin
插件
headline
标题
language
（仅限SSP）语言包
calendar skin
（仅限SSP）日历外观文件
calendar plugin
（仅限SSP）日历的计划传感器
package
（仅限SSP）用于多实例安装的软件包

[旧规格](仅限SSP) 仅填写calendar时，将被视为与calendar skin同等。
这是日历插件calendar plugin的兼容用途，目前已不应再使用。

不可省略

accept,本体侧名

可接收归档的人格的本体侧的名称（＝\0名,sakura名）。
或者也可使用人格端descript.txt文件中设置的install.accept所指定的名称。
在需要向特定人格传递附加Shell或附加文件（supplement）等内容时，务必使用此项。

无任何行为

directory,目录名

该归档文件安装后的目录名。建议使用半角英数字。

不可省略/仅在type,package情况下无需填写。

bootghost,目录名

仅对type,package有效。initial_install.nar或在通过nar关联启动SSP时，指定应启动的Ghost目录名。

  • 2.7.52
refresh,数值

将数值设为1时，会在安装前先删除同一目录下的所有文件。

1以外的任何值（refresh无效）

refreshundeletemask,文件名1:文件名2...

从refresh中排除的文件名。
若有多个，请以冒号「:」分隔。
无法指定路径。所有目录中指定文件名的文件都将被排除。

无任何行为

*.directory,目录名

同时安装的内容在安装后的目录名。建议使用半角英数字。
*部分应填写要同时安装的内容的类型（balloon、headline、plugin、calendar.skin、calendar.plugin 之一）。
当需要安装多个相同类型的项目时，可在*部分后加上数字，如 balloon0、balloon1……，以表示多个实例。
仅在type为ghost或shell时方可进行设置。

无任何行为

*.source.directory,目录名

同时安装的内容在归档文件中的目录名。建议使用半角英数字。
当同时安装的内容在安装后的目录名与归档文件内的目录名不一致时进行设置。

*.directory所设置的目录名

*.refresh,数值

同时安装的内容的refresh设置。

1以外的任何值（refresh无效）

*.refreshundeletemask,文件名1:文件名2...

同时安装的内容的refreshundeletemask设置。

挙動なし

delete.txt

delete.txt

概要

请同时参考文件结构「网络更新」的页面。

客户端（用户）的文件在更新时只会被服务器（作者）的文件覆盖，而不会进行同步。
也就是说，一旦文件在客户端被下载并创建，即使在服务器端被删除，也无法将其移除。
因此，如果在公开后需要删除已公开的文件，就必须将该文件写入delete.txt中。
此外，delete.txt在执行删除操作后也不会自动被删除，一旦写入的内容在未被修改的情况下将永久保持被排除状态。

以下为SSP专用规格。

charset,(字符编码)
指定文件的字符编码

示例

ghost\master\ai.dtx
ghost\master\testdict\
shell\master\surface110.png
相对路径

在网络更新时，以人格主目录的相对路径列出要删除的文件。
相对路径的层级使用“\”作为分隔符。
也可按文件夹单独指定，此时末尾需以\结尾。

无任何行为

developer_options.txt

developer_options.txt

概要

也可参考文件结构「网络更新」・文件结构「安装」的页面。

SSP在创建归档文件或网络更新信息文件时，用于为目标文件设置选项。
通过将人格等软件包的文件夹拖放到SSP中，可生成归档文件（.nar）及更新文件（updates2.dau），该功能在执行时会参照此文件。
因此，原则上，如果使用其他工具，如“そだて”或“ゴースト配布系自動化システム”来创建这些文件的话完全无关，请注意。
不过也有例外，比如“さとりすと”，它实现了读取并使用developer_options.txt的功能。

示例

ghost/master/savedata.txt,noupdate
shell/old/,nonar
ghost/master/profile/,nonar,noupdate

注意事项

请注意，设置应针对单个对象（文件或文件夹）以一行形式进行。例如，若按如下方式编写，则仅会应用位于后方（下方）的设置，而nonar选项将无效。

ghost/master/profile/,nonar
ghost/master/profile/,noupdate

在指定两个选项时，正确做法如前所述

ghost/master/profile/,nonar,noupdate

这样。

相对路径,选项1,选项2,...

对于从人格的主目录出发、以相对路径指定的文件或文件夹，可使用逗号分隔的方式指定选项。
相对路径的层级应使用“/”而非“\”进行分隔。
指定文件夹时，应在末尾添加“/”。
可使用通配符“*”和“?”（自SSP 2.5.17起）
选项的具体内容如下。

nonar
在生成nar时，不将目标对象包含在nar中。
noupdate
在生成updates2.dau（updates.txt）时，不将目标对象纳入更新范围。


由于这些均属于文件创建时的控制措施，因此仅在使用SSP或能够识别本文件的应用程序功能来生成nar、更新文件时才有效，请注意。

无任何行为

自动排除的对象

当SSP生成nar/updates2.dau（updates.txt）时，即使未在developer_options.txt中进行指定，以下文件与文件夹也会被自动排除在外。

文件

  • desktop.ini
  • thumbs.db
  • folder.htt
  • mscreate.dir
  • .DS_Store
  • _CATALOG.VIX

文件夹

  • profile/
  • var/
  • __MACOSX/
  • XtraStuf.mac/

.narignore / .updateignore / .narinclude / .updateinclude

.narignore / .updateignore

为了使developer_options.txt的语法更加灵活，我们直接沿用了.gitignore的语法，将其应用于.narignore/.updateignore。

具体语法请参考 .gitignore的使用手册或者向LLM（文本生成AI）提问，让它为你生成相应的配置。

作为仅限于伺か的特殊功能，有一个include:指定。例如
include:.narignore
这样写的话，会像把整个.narignore文件的内容都插入到这一行的位置一样进行处理。

.narinclude / .updateinclude

.narignore/.updateignore的白名单版本。只有写在这里的内容才会被存入更新文件/NAR中。
对子目录的处理方式与gitignore不同，例如仅写shell/master，而无需再写shell/，系统会自动将父目录也一并纳入处理范围。

updates_def.txt

[旧规格]目前需在developer_options.txt中进行指定。
相对路径,ignore

以相对于人格主目录的路径指定文件，并用逗号分隔选项。
不可按文件夹进行指定。
若存在 ignore 选项，则在创建 updates2.dau（updates.txt）时，不将该对象包含在更新目标中。

无任何行为
